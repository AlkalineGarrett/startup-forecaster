calibration schema · v2 · grounded · constructed · derived

Distributions are built from evidence. Percentiles fall out.

One grounded interpretation per node. The atomic unit is a measure in whatever form the source states it. Each node's distribution is constructed — from atoms with an allocation, or from a fit to source measures, or a weighted combination — and percentiles are a derived readout, never hand-authored. Every example below is a whole node, documents and all, drawn from an illustrative (fictional) dataset.

the shape, at a glance

How a node is put together

A shared corpus of evidence on the left; a node on the right. The node holds named inputs , a distribution (of one kind), and the narrative around it — truncation, reconciliation, cross-checks, a support score — plus a throwaway debug_computed_percentiles readout. Everything the node uses is a reference into the corpus by id; nothing about a percentile is ever stored.

One map. The node holds inputs and a distribution; its distribution (and inputs, and cross-checks) reference into the shared corpus by id — an observation in a document, a general_knowledge prior, a speculation, or a null gap. Each observation's cited_by lists every node that uses it — that shared id is the correlation record. Percentiles are only ever read off the distribution into debug_computed_percentiles; nothing about them is stored.

the model

Seven principles

  1. One grounded interpretation. No rival versions, no rejected alternatives, no back-pointers. Each node states a single distribution and the evidence behind it.
  2. The measure is the atomic unit. Record what the source actually says — a value, an interval, a mean, a mode, or stated percentiles — never force-fit into a p10/p50/p90 template.
  3. Distributions are constructed, not authored. A node's distribution is built from its grounded measures — atoms with an allocation, a parametric family (its params grounded), or a weighted combination of sub-distributions. The object each node contributes is a distribution, not a number; combining nodes into outputs is the simulator's job, not the calibration's.
  4. Percentiles are derived output, never authored. You never hand-guess p10/p50/p90. They are read off the constructed distribution when the simulator needs them.
  5. Widen only on grounded conflict. An interval is wide because the evidence is wide — two grounded sources disagree, or a heavy tail is evidenced. Never widen to hedge or to span a guess.
  6. Heavy tails are modelled, not extrapolated. Where a mean implies a heavier tail than the body quantiles, splice a Generalized Pareto tail (shape set by the mean); never a hard cap.
  7. Everything traces to a source. Every measure references a document/observation or a named reference-class prior. Judgement enters only as a documented adjustment to a grounded distribution.

the schema · field by field

Every record, and the rule each field carries

Documents, observations, and general knowledge live in a shared corpus at the root, referenced by id — node → distribution → reference → observation → document. A fact used by five nodes is one observation with five entries in its cited_by, not five copies. Fields that point elsewhere are ids; the teal tag on the right names the principle the field serves. Nothing about a percentile is ever stored: a node holds a distribution, and debug_computed_percentiles is recomputed from it.

why inputs exist — one value, referenced in several places

The reachable-base centre feeds both the lognormal's median and the contract-flow cross-check (which divides the monthly flow by it). Defining it as in_reachable once — and referencing that id in both places — keeps a single source of truth, so a later revision changes one number, not two. Inline formulas on location/cross_checks could not share a value; inputs is the layer that can.

Invariants

Each is checkable: the build fails if it does not hold. A script verifies shape; support, aboutness, and sameness are read by an agent.

  • I1
    Percentiles are never authored. no node stores input quantiles; debug_computed_percentiles is present only as a recomputed throwaway readout of the distribution. P4
  • I2
    The distribution is complete for its kind. the required fields are present — point_mass: atoms+allocation · weighted_combination: components+allocation · metalog: ≥2 ordered anchors + boundedness · splice: ≥2 segments + a splice each · a parametric kind: all of that family's named params (e.g. lognormal: median+sigma). P3
  • I3
    Constraint holds. the allocation.constraint formula evaluates true — e.g. sum(atoms[].weight) == 1 — and the weight fields are non-negative. P3
  • I4
    Referential integrity. every reference — in allocation, in a truncation bound, in a parametric param — resolves to an observation, general_knowledge, speculation, or a node input. P7
  • I5
    Every measure grounds out. a measure the node uses either matches an observation's own, or is a documented adjustment in reasoning — never a bare number. P7
  • I6
    Verification is honest. verified ⇒ a non-empty quote in the document's core; unchecked/not_in_doc carry no quote; unverifiable carries a blocked_on. A null quote is allowed only with a capture_note and a non-verified state. P7
  • I7
    Widen only on grounded conflict. a wide interval traces to ≥2 grounded sources that disagree (spanned, neither rejected) or an evidenced heavy tail — never to hedging or a guess. P5
  • I8
    Tails are modelled, not capped. a heavier-than-body tail is a splice whose upper segment is a generalized_pareto (shape from the mean, scale slope-matched at the splice) — never a hard cap or a truncation standing in for one. P6
  • I9
    One interpretation. no rival versions, no rejected alternatives, no back-pointers; a node states one distribution and its evidence. P1
  • I10
    Native measure, no template. a measure records only the parts the source states — including a dated series for multi-point sources; no measure is back-filled into a p10/p50/p90 shape. P2
  • I11
    Dedup & correlation. two references to the same (statement, measure) share one observation; which nodes use it is derived on demand from the node references, never stored — that shared id is the only correlation record. P1

    One path to evidence. a node reaches a document only via distribution → reference → observation → its document in the shared corpus; there is no per-node evidence list. P7

    Derived documents show their work. a document with a derivation carries { method, from[ ] } and every from id resolves. P7
  • I14

The series is the source; the formula is the projection. measure.series holds the dated register counts verbatim; extrapolate_cagr(series, 2026) is one of the closed formula functions (I22) — its 2.1%/yr trend and ~15,180 result are recomputable from the series, not a bare number. scope

Where the schema stops: node combination is the simulator's job

Every node in a calibration dataset is an elicited leaf — each holds its own distribution, and none is a formula over other nodes. The schema is for those leaves.

The model does combine them — a Monte-Carlo revenue simulation, one unit per project, with a Gaussian copula over shared factors — but that combination lives in the simulator, downstream of this dataset, and is deliberately kept out of the calibration. As the design notes put it: "these are properties of the simulation, not of the calibration", and "the calibration file is the input the simulation consumes." So the DAG that ties leaves into outputs — and the dependence layer (the copula, the Dirichlet regime-weight coupling) — is the simulator's responsibility, not a distribution kind here.

Grounded kinds only. point_mass, weighted_combination, splice, metalog, and the parametric families (lognormal, beta, …, generalized_pareto) each map to real elicited nodes. There is no propagate: the schema has no formula-over-nodes field, no node references another node, and combination is out of scope by design.
The distribution kinds are worked against illustrative leaves for two fictional products — habit-app (a consumer habit-tracking app) and field-crew (scheduling software for small field-service crews): point_mass (field-crew::platform_bundling_severity), lognormal (field-crew::n_crews_reachable), weighted_combination (field-crew::adoption_rate), beta (field-crew::share_of_jobs_scheduled), normal (habit-app::active_days_per_year), gamma (habit-app::referrals_per_user), uniform (the adoption_rate structural band), and metalog (field-crew::addon::arpu_usd_mo, an observed price list read as an ordered sample) — their evidence (a business register, vendor release notes, an operations survey, an engagement benchmark, vendor pricing, vertical-SaaS base rates) is invented for illustration and drawn from the nodes' own sources. Two further examples show a splice (lognormal body → generalized_pareto tail, habit-app::daily_installs) and measure.series with extrapolate_cagr (field-crew::n_crews_reachable). debug_computed_percentiles are computed from each distribution, shown for reference — never authored. Node combination is the simulator's job, out of scope here. This is the spec the ground-up rebuild works from.
